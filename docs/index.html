critters — spatial-index demos

Live demos for vectorial-hash-kit, a Rust spatial-index library. Watch the index split & merge in real time as critters move, hunt and attack — running right here in your browser via WebAssembly.

2D

2D critters →

Predators & prey on a flat map. A live tuning panel and performance graphs; the index's leaf regions recolour as cells subdivide and merge.
3D

3D critters →

A cube world with GPU-instanced rendering. Press M to switch the index live (binary tree / octree / Morton grid / projection — all O(1)-relocated via stable handles).
3D · wgpu

Siege →

A procedural medieval battlefield: two castles sally their armies and clash. Every unit's brain is a spatial query — k-NN targeting, raycast line-of-fire, sphere-cull AoE, smoke that blocks shots. Renders with real GPU skeletal skinning on WebGPU browsers (Chrome / Edge / recent Safari), and falls back to the WebGL build otherwise.
wgpu · WebGPU

Horde →

A They Are Billions-style assault: a fortified colony vs tens of thousands of dormant zombies. Noise events wake them in cascading sphere-culls, towers auto-target (k-NN), breaches reroute the flood, one fallen house detonates the infection chain — and the sleeping horde costs ~nothing to keep indexed. Needs a WebGPU browser.
wgpu · WebGPU

Formations →

A Total War-style automatic battle: regiments wheel and hold lines, cavalry charges arm over a raycast corridor, archer volleys land k-NN(1) with honest friendly fire, and flank/rear contact (sector classify) bleeds morale until an army chain-routs. Needs a WebGPU browser.
wgpu · WebGPU

GPU broad-phase →

The same neighbour-count query, three backends you flip live — CPU Tree3 · GPU brute · GPU LBVH (a BVH from Morton codes, traversed in a compute shader). Identical picture, wildly different cost. Needs a WebGPU browser.
wgpu · WebGPU · measured

Point cloud →

A big static, strongly skewed cloud — dense on surfaces, empty between them. Every point is coloured by local density from a k-NN query per point; M rebuilds on a different structure and re-runs the whole pass, so build and k-NN times are measured live and cross-checked. This is where the median-split KdTree3 earns its keep. Needs WebGPU.
wgpu · WebGPU · interactive

Fluid (SPH) →

Drag with the mouse or a finger to stir it. A position-based fluid whose neighbour search runs through the kit — the archetypal index workload (every particle wants the ones inside its kernel radius, every step, and a fluid is as clustered as data gets). M switches the index live (Morton grid ↔ kept tree ↔ linear quadtree) and the bars show where the frame goes: maintain vs query vs physics. Needs a WebGPU browser.
wgpu · WebGPU

GPU storm →

A GPU-resident collision storm — the whole hot loop (grid → contacts → integrate) on the GPU, no CPU round-trip. Switch the whole sim CPU↔GPU; F for an influence field. Coloured by local density. Needs a WebGPU browser.

Click the canvas to give it keyboard focus. The first load fetches ~1 MB of WebAssembly. Needs a WebGL2-capable browser. On a phone, tap ⤢ (top-right) to hide the chrome and go fullscreen — the 2D demo scales to fit any screen.
